# 검증과 채택 계약

## 세 층을 구별한다

1. 기계 검사: UTF-8 텍스트, 해시, 검토 ID, 지정 문자열, 일부 자동 추출 보호구간, 수치 토큰, 레이아웃, 분량.
2. 의미 검토: 독해로 주체/대상, 조건, 양태, 시제/상, 수량, 인과, 주장 강도, 필수 정보와 문체를 대조한 검토자의 기록.
3. 외부 사실 확인: 실제 자료를 읽고 특정 주장과 대조하는 별도 작업.

첫째가 통과했다고 둘째나 셋째가 통과한 것은 아니다. 검토 ID를 모두 반환해도 독해 자체를 증명하지는 못한다.
실행기는 독립적인 진실 판정기가 아니며, 리뷰어가 잘못된 `pass`를 반환하면 의미 오류가 통과할 수 있다.

## 12개 검토 차원

| Key | 확인할 관계 |
| --- | --- |
| meaning | 문장의 명제와 글 전체의 뜻이 유지되는가 |
| entities_roles | 행위 주체, 수혜자, 대상, 발언자가 바뀌지 않았는가 |
| negation_conditions | 부정, 조건, 예외, 제한이 유지되는가 |
| modality_scope | 가능/허용/의무/사실, 일부/전체, 확신 정도가 유지되는가 |
| tense_aspect | 과거/현재/미래, 시작/진행/완료가 유지되는가 |
| numbers_bindings | 값과 단위뿐 아니라 해당 항목과의 연결이 유지되는가 |
| causality_attribution | 상관을 인과로 바꾸거나 발언 귀속을 변경하지 않았는가 |
| required_information | 필수 주장, 예외, 근거, 사례가 빠지지 않았는가 |
| voice_genre | 말투와 장르가 목적에 맞고 원래 목소리가 살아 있는가 |
| no_new_errors | 수정으로 같은 수준 이상의 새 오류를 만들지 않았는가 |
| evidence_fidelity | 제공된 근거를 왜곡하거나 사실처럼 보이는 새 정보를 넣지 않았는가 |
| edit_scope | 작업 모드와 명시된 편집 권한을 지켰는가 |

각 evidence에는 실제 대조 지점을 짧게 적는다. '검증 완료' 같은 공통 문구로 채우지 않는다.
관련 차원의 내용이 전혀 없으면 그 사실을 근거로 적을 수 있다. 확인할 자료가 필요한데 없으면 `uncertain`이다.
`evidence_fidelity: pass`는 제공된 자료와의 충실성 판단이지 인터넷 전체의 사실 검증이 아니다.

## 채택

기계 검사 통과 + 모든 차원 pass + 필요한 문제 1개 이상 해결 + 새 오류 없음일 때만 accept.
개선 여부가 애매하면 needs_review, 의미 손상이나 명백한 퇴행은 reject.
기본 실행기는 후보 전체를 채택하거나 기각한다. 검증 실패 후 임의로 일부만 끼워 넣지 않는다.
유효한 부분만 남기려면 새 후보를 만들고 전체 검증을 다시 수행한다.

## 비교 편향 줄이기

검증 단계에 수정자의 자화자찬은 전달하지 않는다. 원래 자료와 현재/후보 문장을 직접 비교한다.
원한다면 호스트에서 A/B 순서를 바꾸어 추가 검토할 수 있으나 실행기가 자동으로 수행한다고 보고하지 않는다.
서로 다른 모델의 동의도 증거의 대체물이 아니다. 객관적 사실은 해당 자료, 규범은 확인 가능한 규범으로 검사한다.

## 되돌리기와 종료

원문, 생성 초안 baseline, brief는 세션 도중 바꾸지 않는다. 마지막 후보가 아닌 마지막 통과본을 보존한다.
실패, 불확실, 무수정, 같은 후보 재등장, 라운드 상한에서 종료한다. 비용을 늘려 횟수를 채우지 않는다.
프로토콜 오류나 통신 장애에서는 마지막 통과본을 내보내고 중단 단계를 재개 가능하게 남긴다.
해시 불일치처럼 저장 무결성이 깨진 경우에는 파일을 조작해 통과시키지 말고 새 세션으로 복구한다.
